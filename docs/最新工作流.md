# 当前默认工作流

2026-11-17确认。完成本机配置后，在本项目说：

> 帮我做关于〔实际选题〕的视频

Agent自行完成整套交付，已有确认环节和工程接着做，不重复初始化、换声或要求常规确认。

1. 读根配置、写作规则和实际技能。消费、商业、事件与时事调查选 `investigation-video`；其他讲解选 `whiteboard-video`。当次明确指定优先。
2. 查证并保存来源台账，按写作配置起稿，实际执行 Humanizer-zh → stop-slop → taste-skill适用规则，再核对事实与口播。保留证据强度；范围说明拆成画面注记。
3. AI结合选题、目标观众、使用场景和已有数据，在工程根目录写 `受众审查.json`。没有真实统计就标明编辑判断，不编造男女比例，不把题材刻板印象当统计。
4. 男性受众倾向：小天2.0、悠悠君子2.0等概率随机；女性受众倾向：心灵鸡汤2.0；无明显倾向：三者等概率随机。只抽一次，保存 `旁白选择.json`，整片与重试续作用同一声音。
5. 小天1.1倍、悠悠君子1.1倍、心灵鸡汤1.2倍，使用火山原生语速，不重复后期变速。音频与词时间戳同次产生，完整文本、实测时长与时间范围校验通过后，才接镜头和字幕。失败停止，不自动换声或服务。
6. 调查片用真实素材、可读证据和按叙事类型设计的MG；讲解片用手绘白板。MG数值与关系必须有依据。范围说明在对应画面可读、不进入TTS及SRT。
7. 沿用本机品牌、字体和配乐；真实旁白检测触发闪避混音，开头1.5秒淡入、尾部3.5秒淡出，整曲按需循环。缺少已配置音乐时报告并补齐，不以无配乐当完整验收。
8. 导出成片和字幕；分别生成4:3、3:4两张封面并后期合成固定字标。生成抖音、哔哩哔哩、小红书、微信视频号四平台标题与正文，各平台可复制TXT；微信公众号另写一个标题和完整Markdown文章，MD/TXT保留Markdown。
9. 完整解码、尺寸/帧率/音轨检查，核对字幕与旁白原文和真实时间，实际抽帧检查范围注记、证据与字标，播放抽检。记录做了什么；没有全片人工听审就明确注明。
10. 依据 `交付包规范.md` 验齐后打包：成片、SRT、双封面、四平台文案、公众号全文、来源台账、素材使用区间、审校及检查记录、交付清单。制作与备稿不包括公开发布。

声音ID与池在 `workflow/旁白音色配置.json`，开关在 `config.json → tts.voicePolicy.enabled`。明确指定某期声音可覆盖随机池，必须记录当次用户指令；不因此改变后续所有选题。

参考账户已经完成三音色短段及一条约3分23秒调查片的真实制作；新使用者仍须配置自己的凭证和资源权限。本包不含原作者密钥、克隆音色、音乐、新闻原片或未发布成片。
